实施分支：`feat/product-analytics`。保留旧循环根工件及用户未提交文件；本需求的实现与验证证据记录在本文和专用验证文档，合并/生产发布仍需人工批准。

## 目标与方案

使用自托管 Umami，提供页面访问、访客、来源和自定义事件统计；运营者使用独立 Umami 管理员账户查看。Zeabur 部署服务并提供管理入口，不把容器日志视为统计看板。Umami 软件免费，Zeabur 运行资源可能产生费用；不承诺额外基础设施零费用。生产资源配置和发布另行人工批准。

使用独立 Umami 数据库及受限数据库账户，不让 Umami 初始化业务数据库。部署固定版本官方预构建镜像，首次开放前更改默认管理员密码，关闭公开分享；密钥仅由环境变量提供。上线前记录镜像版本、数据库备份和实际资源成本。

## 事件与完成口径（随方案批准）

| 事件 | 触发 | 去重与可信来源 |
| --- | --- | --- |
| pageview | 公共页面及 SPA 路由访问 | 浏览器路由单次上报，StrictMode 不重复 |
| registration_completed | 新用户持久化成功 | 后端记录，每账户一次，覆盖邮箱/手机/Google |
| first_conversation_started | 真人场景收到首条有效用户发言 | 后端确认，每账户一次；打开页面/WS 建连不算 |
| first_conversation_completed | 真人场景至少一次完整用户回答与 AI 回复，且用户明确结束/返回，或后端确认整个场景完成 | 后端确认轮次、模式、会话归属；每账户一次 |

“一场对话完成”默认采用上表口径，不要求完成整个学习目标。关闭标签页、断网、刷新不自动视作完成；已有服务器结束证据可重试入账。tour、recall、daily_qa、magic_repetition 排除；同页进入真人阶段后以服务端当前阶段判定。不得拿任务分数、99% 或单个子任务完成冒充整场场景完成。

统计注册队列的首次完成率：同一注册时间区间内的新账户中，完成首次对话的比例；提供截至查询时累计值及固定 7 天转化值，未满 7 天标记观察中。不能用当日完成事件数除以当日注册数。Umami 原生漏斗存在步骤时间窗口，跨日/跨设备队列以服务端去重账本为准，并在受保护报表中提供可核对的汇总。

## 数据边界

- 访问统计仅发送规范化路径和允许的来源字段；去除 query/hash、动态标识、场景名和页面标题中的用户内容。
- 不发送手机号、邮箱、昵称、用户文本、音频、JWT、原始业务 userId；不启用回放。
- 业务去重账本保留内部用户关联与时间。Umami 如需关联使用随机分析标识，仍按可关联数据处理，限制访问与保留期；删除账户清理关联数据。
- 默认保留分析事件 90 天；上线前核对隐私说明、目标地区及必要的同意机制，拒绝统计时不发送可选分析数据。测试流量进入独立测试站点。

## 必须验证

- 注册三种入口仅新用户一次；失败、事务回滚、已有账户登录不产生注册事件。
- 真人完整轮次与结束才完成；空会话、只有 AI 欢迎语、断线、排除模式不完成；伪造 userId/sessionId/mode 被拒绝。
- 同账户跨标签页、重连、跨设备、重复结束均只有一个首次完成；跨日队列分母分子可核对。
- 采集失败与重试不影响业务、不丢本地事件；记录外部投递重复风险与汇总纠偏方式。
- SPA 首次与导航各一次；请求不包含敏感参数、对话文本或账户信息；停用后不发采集请求。
- 普通账户/未登录无法看管理数据；管理员能看到实际 PV、来源和注册→首次完成数据。
- 按变更运行 user-service、conversation/history、ai-omni 的专项测试及前端测试；`cd client && npm run build`、仓库 `npm run verify`、secret scanning 与 PR checks。
- 生产记录实际部署 SHA、Umami 版本、采集 HTTP 结果、后台可见测试访问、专用测试新账户全链路、重复结束无重复计数。仅脚本加载成功不算完成。
